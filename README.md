# ProjectAgent

Личная Windows-утилита: ИИ-агент по **выбранной папке проекта**. Не замена IDE — навигация по коду удобнее в VS Code рядом.

- Python 3.11+, UI на CustomTkinter
- Один exe через PyInstaller (`build.ps1` → `dist\ProjectAgent.exe`)

## Запуск

```text
.venv\Scripts\activate
python -m project_agent
```

Тесты:

```text
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Сборка exe (только по необходимости):

```text
.\build.ps1
```

Конфиг и данные: `%APPDATA%\ProjectAgent\` (`config.json`, чаты, индекс путей). Пример полей — `config.example.json`.

## Что умеет агент

Агент **не кладёт весь проект в контекст**. Нужные файлы читает инструментами или получает из явных вложений.

### Файлы проекта

| Инструмент | Возможность |
|---|---|
| `list_dir` | Список файлов/папок на один уровень |
| `read_file` | Чтение текста с номерами строк (лимит размера) |
| `search` | Поиск подстроки по текстовым файлам |
| `write_file` | Полная перезапись файла (**только после подтверждения**; в диалоге — краткий diff) |
| `apply_patch` | Правка SEARCH/REPLACE или unified diff (**с подтверждением** и diff) |
| `view_image` | Просмотр изображения из проекта |
| `project_index` | Лёгкий индекс **путей** (`summary` / `refresh` / `find`) — не содержимое, не семантика |

Игнор каталогов для доступа агента: `.git`, `__pycache__`, `node_modules`, `.venv`, `dist`, `build`.  
Файлы больше **1 МБ** и бинарники не отдаются как текст.

### Контекст в запросе (без «всего проекта»)

- `@путь` в поле ввода + подсказки из индекса
- «+» → файл проекта или изображение
- ПКМ по файлу в дереве → «Вложить в запрос»
- В модель уходит только содержимое явно вложенных файлов (лимит числа/размера, секреты маскируются)

### Правила проекта

Подхватываются в system prompt:

- `AGENTS.md` в корне
- и/или `.projectagent/rules` (файл или папка `.md` / `.txt`)

Показываются в **Настройки → Проект**.

### Тесты

- `run_tests` — только пресет из настроек: **unittest** или **pytest** (не произвольный shell)
- Каждый запуск с **подтверждением**
- Таймаут, обрезка вывода, лимит запусков за ход (`test_fix_rounds`)
- Стоп убивает процесс; повтор того же FAIL останавливает цикл правок

### Git

Инструмент `git`, без свободного shell:

| action | |
|---|---|
| `status` | Краткий статус |
| `diff` | Diff (опционально путь / staged) |
| `log` | Недавние коммиты |
| `commit` | Только после подтверждения; staging через `paths` или `add_all` |

**Нет:** `push`, `reset --hard`, произвольные git/shell-команды.

### Интернет и картинки

- `web_search` — поиск (секреты в запрос не передаются)
- `generate_image` — генерация и сохранение в проект (**с подтверждением**), если задана модель изображений

### MCP

- `list_mcp_tools` / `call_mcp_tool` — вызов настроенных MCP-серверов
- Секреты в аргументы MCP не подставляются

### Секреты

- Пароли/ключи маскируются метками `[[SEC:…]]`
- Запись с метками восстанавливает исходные значения после подтверждения
- Нельзя «протащить» секреты в web_search / generate_image / MCP

## Интерфейс

- Полоса слева (проект, настройки), боковая панель: папка, «Новый чат», вкладки **Чаты | Файлы**
- Чат: пузырь «Вы», подпись «Ассистент», markdown (код/жирный)
- Под ответом ассистента — иконка **копирования** реплики
- Копирование из чата: Ctrl+C/С (EN/RU раскладка), ПКМ «Копировать» / «Выделить всё»
- Поле ввода: карточка, placeholder, плюс, send↔stop, профиль/модель/статус, высота запоминается
- Панель файла — по клику на файл в дереве, тянется по ширине
- Темы **light/dark** (`theme` в config)
- Настройки по разделам: Внешний вид, Модель, Изображения, Проект, MCP, Безопасность
- Удаление чата: ПКМ → Удалить
- Профили моделей, запись config с повтором при WinError 5

## Намеренно нет

- Свободный терминал / произвольный shell
- Семантический индекс / embeddings
- LSP / встроенный IDE-редактор полного цикла
- Push в remote и разрушительные git-операции

Цель: агент по папке + VS Code сбоку для навигации.
