# Правила проекта

Этот файл содержит обязательные правила для агентов, работающих с проектом ProjectAgent.

## Работа с кодом

- Перед изменениями прочитай связанные модули, импорты и тесты.
- Сохраняй существующую архитектуру и локальные соглашения проекта.
- Не изменяй несвязанные файлы и не удаляй пользовательские изменения.
- Для ручных правок используй точечные изменения; избегай массового переформатирования.
- Не добавляй секреты, API-ключи и содержимое пользовательского `config.json` в исходный код, логи или документацию.

## Тесты

- После изменений запускай тесты через настроенный пресет `run_tests`.
- Допустимые пресеты: `unittest`, `pytest`, `npm` (`npm test`). Пустой пресет означает, что автоматический запуск тестов выключен.
- Учитывай таймаут тестов и лимит повторных запусков из настроек проекта.
- При падении сначала анализируй фактический вывод и исправляй причину. Не повторяй тот же неуспешный запуск без изменения причины или входных данных.

## Allowlist и сборка

- Для разовых команд используй `run_allowed` только с id из allowlist.
- Встроенные id: `unittest`, `pytest`, `npm_test`, `build_ps1`.
- `unittest` запускает обнаружение тестов из каталога `tests`; `pytest` запускает pytest; `npm_test` запускает npm test; `build_ps1` запускает корневой `build.ps1` через PowerShell.
- Пользовательские команды allowlist имеют формат `id: arg1 arg2 ...`. Суффикс `!` означает запуск без ожидания завершения для GUI или долгого процесса.
- Не выдумывай id, аргументы или команды, которых нет в текущем allowlist.

## Shell и подтверждения

- `run_tests`, `run_allowed` и `run_shell` выполняются только после подтверждения пользователя.
- `run_shell` используй только в режимах Agent или Debug и только если нет подходящего тестового пресета или allowlist-id.
- Для `run_shell` передавай argv без shell-метасимволов. Не используй `cmd` и `powershell -Command`; для PowerShell нужен режим `-File`.
- Не запускай интерактивные терминалы. Для GUI или длительного процесса используй `detach=true`.
- Не выполняй destructive-команды, включая `git reset --hard` и `git checkout --`, без явного запроса пользователя.

## Файлы проекта

- Правила проекта находятся в `AGENTS.md` и подхватываются в system prompt.
- Конфигурация приложения хранится вне репозитория в `%APPDATA%\\ProjectAgent\\config.json`; не копируй ее в проект.
- `config.example.json` содержит только пример структуры и не должен использоваться как хранилище секретов.
- При изменении поведения обновляй связанные тесты и документацию, если это необходимо.

## Git

- Перед правками учитывай текущее состояние рабочей копии.
- Не откатывай изменения, сделанные пользователем или другими агентами.
- Коммит создавай только по явному запросу пользователя.
